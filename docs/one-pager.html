One-page design brief

Monte Carlo Schedule Estimator

Every project plan is a single number that nobody attaches a probability to. This tool takes the three-point estimates a manager already has and answers the question they actually mean: how likely is that date?

Stack Python · Streamlit · NumPy · matplotlib Input one Excel file Runs on a laptop, offline

The problem, in numbers

The plan says 149 days. The simulation says that date has a 12% chance.

The example below is a real 12-task delivery project. The planned date is the sum of every "realistic" estimate — the number almost every plan reports. Ten thousand simulations put a safe commitment 52 days later.

149 days

Output

Two charts, built to be pasted into a deck

Both export as 300 dpi PNG with one click. Nothing on them needs explaining out loud.

How it works

Five steps, in order, every run

01 · LOAD

Read the file

Any .xlsx or .xls. Pick a sheet if there is more than one.

02 · MAP

Find the columns

Column names are matched against a synonym list. You confirm the guess.

03 · CHECK

Report bad rows

Text in a number cell, negatives, best case above worst case.

04 · SIMULATE

Run it 10,000 times

Each task gets a random duration; the totals build a distribution.

05 · REPORT

Dates and charts

P50, P85, P95 as durations and calendar dates. Two PNGs, one Excel summary.

The maths, in plain words

Three decisions, and why each one is defensible

Triangular shape

Each task's random duration is drawn from a triangle: it cannot fall below the best case or above the worst case, and it lands near the expected value most often. It needs no number the manager has to invent.

o ≤ duration ≤ p, peak at m

Parallel streams

Add a Stream column and tasks in the same stream run one after another, while streams run side by side. Without that column the tool adds everything up — correct for a sequential project, and stated openly when it is not.

total = max(sum s₁, sum s₂, …)

Correlation

Real tasks slip together — one thin team, one slow client. Assuming they are independent lets the errors cancel out and makes the forecast look far more precise than it is. One slider, default 0.3, controls how much they move as one.

Z = √ρ·Z_common + √(1−ρ)·Z_task

Architecture

Thin screen, thick core

The interface knows no mathematics and the mathematics knows no interface. Every core function takes plain numbers and returns plain numbers, so all of it is testable without opening a browser — and swapping Streamlit for a command line later touches exactly one file.

app.py

Streamlit screens. Widgets and orchestration only — no arithmetic.

core/loader.py

Excel bytes to a table. Drops blank rows and columns.

core/mapping.py

Header to role. Exact match, then synonyms, then fuzzy match.

core/validate.py

Returns a list of problems, never raises. Errors block, warnings do not.

core/simulate.py

The 10,000 runs. One matrix, no Python loop, fixed seed.

core/stats.py

Percentiles, the plan baseline, the odds of a target date.

core/dates.py

Duration to calendar date. 5- or 7-day week.

core/charts.py

The two figures. Returns them; never writes files itself.

Scope

What ships, and what deliberately does not

In version 1
  • Excel upload with automatic column detection
  • Validation report you can act on
  • 10,000 triangular simulations, fixed seed
  • Optional parallel streams and correlation
  • P50 / P85 / P95 as durations and dates
  • The planned date, and its real probability
  • Histogram and S-curve as 300 dpi PNG
  • Excel summary export
Not in version 1
  • Dependency graph and true critical path
  • Resources, cost, budget simulation
  • Which task drives the risk (tornado chart)
  • Per-task correlation instead of one slider
  • Alternative distribution shapes
  • Saved projects, accounts, a server
  • Public holiday calendars
  • Direct PowerPoint export

Build plan

Four phases, each one runnable

Phase 1

The engine

Simulation, statistics and dates, with tests, before any screen exists. Verified against a hand-computed example.

Phase 2

Getting data in

Loader, column mapper and validator, tested against messy real-world headers in English and Russian.

Phase 3

The screen

Streamlit wiring, settings, results, error handling. First point where the tool is usable end to end.

Phase 4

Presentation quality

Chart styling for a projector, PNG and Excel export, sample file, README.
